# Fuzz targets

| Target | Input | Entry point |
|---|---|---|
| `fuzz_loader` | an index file image | `LoadedIndex::from_memory` (the validation `LoadedIndex::open` runs), then `open` in Read mode from an in-memory file |
| `fuzz_fvecs` | an fvecs/ivecs file | `read_fvecs`, `read_ivecs` (from an in-memory file) |

`fuzz_loader` searches an image only if deep validation accepts it, and checks
that the in-memory and Read-mode paths agree. `fuzz_loader_mutator.cpp` fixes the
header CRC after each mutation so mutations reach the checks behind it.

## Layout

- `seeds/<target>/`: small hand-picked inputs, generated by `gen_seeds.sh <build-dir>`
  (valid files of several shapes and a few invalid variants).
- `corpus/<target>/`: inputs found by fuzzing that add coverage beyond the seeds
  (minimized with `-merge=1`; written by `scripts/run_fuzz.sh`).
- `crashes/<target>/`: inputs that once crashed, kept as regression tests.
- `<target>.dict`: libFuzzer dictionaries.

The `fuzz_replay_loader` and `fuzz_replay_fvecs` ctest tests replay all three
directories through the same `LLVMFuzzerTestOneInput` without libFuzzer, in every
build, including the sanitizer builds.

## Running

```
cmake -S . -B build-fuzz -DCMAKE_CXX_COMPILER=clang++ -DHNSW_SANITIZE=address,undefined \
      -DHNSW_BUILD_FUZZ=ON
cmake --build build-fuzz -j
scripts/run_fuzz.sh build-fuzz loader 1800 4   # log: docs/evidence/fuzz_loader.log
scripts/run_fuzz.sh build-fuzz fvecs 300 4
scripts/fuzz_summary.py docs/evidence/fuzz_loader.log docs/evidence/fuzz_fvecs.log \
  > docs/evidence/fuzz_summary.json
```

A new crash: minimize it (`fuzz_<target> -minimize_crash=1 -runs=100000 <input>`),
fix the bug, and add the input to `crashes/<target>/`.
